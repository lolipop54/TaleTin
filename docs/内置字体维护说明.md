# 内置字体维护说明

更新日期：2026-10-11。

字体列表顺序固定为：原书字体（仅适用时显示）→ 系统字体 → 内置字体 → 设备其它字体。全局字体设置和阅读页字体选择共用该顺序；内置字体之间的顺序由下面的Dart目录决定。

内置字体默认随APK一起打包；使用 `--dart-define=GT_INCLUDE_PRESET_FONTS=false` 时，Android 安装包排除完整内置字体和名称预览，字体列表也不显示这些选项。系统字体、设备字体、EPUB 自带字体及固定寄语手写字体继续可用。**只往文件夹放文件或删除文件，还不会自动更新字体列表**，需要同步修改字体目录和打包配置，再重新构建安装包。

字体选择列表使用只含名称文字的小字体预览，正文仍使用完整字体。预览放在`assets/fonts/preview/`，由工具生成，不要把完整字体放进该目录。增删、替换、改名或调整顺序后，按下方步骤重新生成；工具读取实际目录配置，不固定字体数量，普通／粗体分别生成并保留字形和间距。

## 新增一套字体

1. 将TTF文件放进`assets/fonts/preset/`。只有普通版时可直接放一个文件；有独立粗体时建同名字体文件夹，把普通版和Bold版放在一起。
2. 在`lib/platform/channels/preset_fonts.dart`的`catalog`中添加条目。插入位置决定它在内置字体列表中的位置。`name`只填显示名称，不写“（内置）”，界面会自动添加。`families`根据构建参数取完整目录或空目录，不要手动改它。
3. 在`pubspec.yaml`的`flutter: fonts:`下注册相同字体编号、普通版和粗体路径。普通版明确写`weight: 400`，独立粗体明确写`weight: 700`，不要依赖字体文件内部可能不准确的字重标签。
4. 运行下方的预览生成命令。工具会自动生成小字体、更新YAML中`BEGIN GENERATED FONT PREVIEWS`到`END GENERATED FONT PREVIEWS`之间的注册信息和`preset_font_previews.dart`；这两处不需要手动填写。

例如有普通与粗体两个文件：

```text
assets/fonts/preset/示例字体/示例字体.ttf
assets/fonts/preset/示例字体/示例字体-Bold.ttf
```

Dart目录条目：

```dart
'gt-preset-example': (
  name: '示例字体',
  file: '示例字体/示例字体.ttf',
  bold: '示例字体/示例字体-Bold.ttf',
),
```

`pubspec.yaml`中与其它`- family:`条目对齐：

```yaml
    - family: gt-preset-example
      fonts:
        - asset: assets/fonts/preset/示例字体/示例字体.ttf
          weight: 400
        - asset: assets/fonts/preset/示例字体/示例字体-Bold.ttf
          weight: 700
```

只有普通版时，Dart的`bold`写`null`，YAML只保留400条目；用户开启加粗时沿用渲染器合成粗体。字体编号使用唯一的`gt-preset-英文编号`，不要以`-bold`结尾，这个后缀留给原书排版访问粗体文件。

## 删除、替换或调整顺序

- **删除**：同时删除preset文件夹中的对应文件、Dart的catalog条目、YAML的对应family整段。其它字体的编号保持不变。若手机已选择该字体，更新后会先准备系统字体，再用系统字体显示；保存的旧编号不主动改写，用户重新选字体后才覆盖。
- **替换字体文件**：同一字体的新版本可以保留原编号、名称和路径，替换文件后重新打包；如改路径，需要同步改Dart目录和YAML路径。
- **仅改显示名称**：修改Dart条目的`name`，不要改已使用的编号。
- **调整内置顺序**：移动Dart的catalog条目位置即可，YAML条目顺序不影响字体列表。

以上操作完成后，都运行一次生成工具。删除字体时只改原始字体的目录及注册项，工具会清掉不再使用的预览文件和注册；改名会更新预览所需文字。完整字体文件不会被生成工具修改。新增或改名后忘记生成时，列表会用完整字体显示该名称，功能仍可用，但首次打开可能较慢。

## 生成与检查小字体预览

Python环境第一次使用时安装开发工具（应用运行不需要Python）：

本次生成使用 fonttools 4.66.1、PyYAML 6.0。不同工具版本可能生成不同的二进制字节，重新导出后需再次运行检查。

```powershell
python -m pip install fonttools PyYAML
```

在项目根目录运行：

```powershell
python tools/fonts/generate_previews.py
python tools/fonts/generate_previews.py --check
```

第一条根据Dart目录中的名称和YAML中的完整字体路径／字重生成预览，保留字体的版权和许可信息，并检查名称字形及字距与原字体一致。第二条只检查，不写文件；漏生成、删除后遗留预览或改名后没有更新时会报错。预览字体编号只用于列表显示，保存的仍是原完整字体编号，不影响全局应用、仅阅读页应用及单书覆盖。

生成工具自身的增删、改名回归可运行：

```powershell
python tools/fonts/test_generate_previews.py
```

该测试在临时目录中实际新增、删除、改名和检查普通／粗体配对，不修改项目字体。

## 固定寄语手写字体

日期明细的固定寄语放在 `lib/ui/features/achievements/widgets/reading_day_summary.dart` 的 `readingDayQuote` 常量中。安装包中的 `assets/fonts/reading_quote/LongCang-Regular.ttf` 只含这段文字需要的字形；完整来源保留在 `tools/fonts/source/LongCang-Regular.ttf`，不进入安装包。生成时核对字形、间距与原字体一致，保留许可，并给裁剪后的字体使用独立内部名称。

修改寄语后，在项目根目录重新生成和检查：

```powershell
python tools/fonts/generate_quote.py
python tools/fonts/generate_quote.py --check
```

不要用该小字体显示其它可变文字。生成工具与名称预览使用同一套 Python 依赖。

## 检查并重新打包

在项目根目录运行：

```powershell
python tools/fonts/generate_previews.py --check
flutter pub get
flutter test test/widgets/preset_fonts_test.dart test/widgets/reader_font_sheet_test.dart
flutter build apk --release
```

资源校验会核对完整字体与预览字体的TTF、Dart清单和实际打包清单是否一致，并检查独立粗体的700注册、预览体积及保存编号，不固定字体数量。漏改注册、路径错误或只删除其中一处时会失败。

不带内置字体的 Android 构建与回退检查：

```powershell
flutter test --dart-define=GT_INCLUDE_PRESET_FONTS=false test/widgets/unavailable_preset_fonts_test.dart
flutter build apk --release --split-per-abi --dart-define=GT_INCLUDE_PRESET_FONTS=false
```

Android 在合并资源后为当前构建生成独立副本，排除 `preset/`、`preview/` 和对应 `FontManifest.json` 条目。构建结束还检查最终 APK，防止只隐藏列表却仍把字体装进包。下次省略参数或传 `true`，字体自动恢复打包，不需改 `pubspec.yaml`。

新增或删除资源需要完整构建；热重载不能代替重新打包。安装包默认在`build/app/outputs/flutter-apk/app-release.apk`，发新版前同时递增`pubspec.yaml`中的版本构建号。手机验证全局应用、仅阅读页应用，以及简化／原书、普通／加粗是否显示正确。字体仍受原有全局默认与单书覆盖规则控制。
